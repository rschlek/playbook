# Define is parked, and guide-me does not offer it

Question: Should `guide-me` keep offering `define` first for new work with no problem definition?

`define` was released with `guide-me` offering it first for any new work with no problem definition. Tried the same day on a real idea, it read as a form, and being offered it at the start felt like a step in the way. It stays in the plugin, starts only when asked for, and is looked at again later.

## What was decided

1. `define` stays in the plugin. It starts only when the user plainly asks to define or write down the problem.
2. `guide-me` goes back to its earlier ladder: a loose want leads to `grill-me`. It does not look for problem definitions.
3. The two map questions about what follows a defined problem are set aside. They return only if `define` is taken up again.
4. `define` is looked at again after it has been tried on a problem that several people need to agree on. Noted for then: show a rough draft after two or three answers, say what does not add up, and ask only about holes in the draft.

## Options considered

- Removing `define`: not taken. The written problem, with what is still unknown and who could answer it, is something no other skill produces.
- Improving it now: not taken. One trial is too little to design from.
- Leaving it offered first: not taken. A step in the way at the start may put newcomers off.

## What settled it

- One trial on a real idea: eight questions in one fixed shape, no draft shown, nothing questioned, and guesses drawn from context a new user would not have.

## Not settled here

- How `define` runs once it is taken up again.
