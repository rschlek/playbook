# Project work goes to the project tracker by default

Question: Is "outcomes" the default level for what goes to the project tracker?

No. By default everything that is the project's work goes in the project tracker, planning included, also for a person who uses a personal tracker. "Outcomes" is a level a project chooses in its tracker doc. What is only one person's own goes in their personal tracker, and so does anything the agent cannot place.

## What was decided

1. The default level is everything. Maps, plans, their steps, and single tickets that are the project's work go in the project tracker. It is work the project needs, and someone else may do it.
2. Outcomes is a level a project chooses. When the project tracker's doc says so, the project tracker gets one ticket for each outcome of a plan, or a link to a ticket that already exists, and the map, the plan, and its steps go in the personal tracker, linked to the outcome they serve.
3. What is only the person's own goes in the personal tracker at every level: reminders, routines, learning, preparation for their own planning, and anything they mark as private.
4. When unsure, personal. An item the agent cannot place as project work or the person's own goes in the personal tracker, and the agent says where it put it. The person can share it later.
5. Set once, not asked each time. The level comes from the project tracker's doc. The agent does not ask ticket by ticket.

## Options considered

- Outcomes as the default for every project: not taken. It hides planning from the people who might do it, and a team that uses playbook wants to see it.
- Every step, with no way for a project to say otherwise: not taken. A project tracker with its own structure may not take planning tickets.
- Nothing unless asked: not taken as a default. The project tracker would stop showing the state of the project.
- When unsure, the project tracker: not taken. What other people have seen cannot be taken back.
- When unsure, ask: not taken. Asking ticket by ticket was ruled out before the map was charted.
- Everything by default, a level chosen in the project tracker's doc, and personal when unsure: taken.

## What settled it

- The person's model: the project tracker answers "what is the state of the project, and who is working on what", and the personal tracker answers "what do I need to do today".
- Planning is work someone has to do, and it does not have to be the person who filed it.
- Sharing later is cheap, and un-sharing is not possible.

## Not settled here

- Where in the project tracker's doc the level is written, its exact form, and how `to-tickets` and `capture` apply it under one yes. A separate question on the map holds these.
- How a person later shares planning kept in the personal tracker with the project. A separate question holds it.

## Replaces

Nothing. It builds on the decision on keeping a linked pair in step, which first recorded where planning lives.
