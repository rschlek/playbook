# Playbook

The words playbook uses for where a project's tickets live, how one person's own list relates to them, and the documents its skills write.

## Language

**Project tracker**:
The tracker everyone on a project sees: its milestones, its shared work, and the tickets assigned to each person. It may be split by ticket kind into a primary and a secondary.
_Avoid_: Team tracker, shared tracker, group tracker

**Split project tracker**:
A project tracker kept in more than one place by ticket kind: a primary, which holds maps, plans, and every ticket not filed elsewhere, and a secondary for each kind of ticket filed elsewhere, such as code tickets. Everyone on the project sees every part.
_Avoid_: Two trackers, dual tracker

**Personal tracker**:
One person's own list, seen only by them, across every project they work on. An item in it may point at a ticket in a project tracker or stand alone.
_Avoid_: Personal board, private tracker, personal layer, extension

**Link**:
The pointer a personal item carries to one ticket in the project tracker. It lives only on the personal side, and several personal items may carry a link to the same ticket.
_Avoid_: Mirror, copy, sync pair

**Problem definition**:
A written account of a problem, made before any way of solving it is chosen: what the problem is, who has it, what it costs, what solved looks like, and what is still unknown. It holds no solution.
_Avoid_: Problem brief, problem statement, requirements document
